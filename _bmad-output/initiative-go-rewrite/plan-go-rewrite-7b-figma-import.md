## Intent

**Problem:** Pasting design content copied from Figma into the editor goes through `core/src/figma.rs`, which decodes the clipboard HTML into `.pen` nodes. The Go core cannot decode it.

**Approach:** Port `figma.rs` to a new `core-go/figma` package with the same `Decode(html) ([]Node, bool)` result: nodes as ordered JSON values with their `(x, y, w, h)`.
- Payload: `data-metadata`, then the base64 between `(figma)` and `(/figma)` with whitespace stripped, then the `fig-kiwi`/`fig-jam.` archive with version and length-prefixed chunks.
- Chunks: raw deflate through `compress/flate`, or zstd through `github.com/klauspost/compress/zstd`, with the 256 MB output cap and Rust's short error messages.
- The kiwi binary-schema decoder: varuint/varint, rotated float32, uint64, enums, structs and messages into JSON, with byte arrays as hex and a depth cap of 64.
- Document building: the guid map, children sorted by position string, blobs, variable sets and modes, styles.
- Conversion: first visible page, style and variable binding, instance expansion with overrides, derived data and swaps, the per-node conversion (types, transforms to rotation and flips, sizing, radius, arcs, polygons, text, paints with image placeholders, gradients, effects, strokes, auto layout) with the 100k node budget, and vector networks to SVG path data.

A test-only Rust CLI subcommand dumps `decode` output as JSON for parity.

## Boundaries & Constraints

**Always:**
- The JSON output for the same clipboard HTML is byte-identical to Rust's `decode` (key order through `jsonv`, Rust float formatting including `{:.3}` and `-0`→`0`). That holds for `core/tests/figma-clipboard.html` and every other fixture.
- Same failure behaviour: `None` (Go: `ok=false`) wherever Rust returns `None`, and the same short error text from the inflate cap.
- One new dependency is allowed: `github.com/klauspost/compress` (pure Go), for zstd. Raw deflate uses the standard library.
- The decoder never panics on malformed input. Byte, depth and node limits match Rust.
- No cgo in this package.

**Never:**
- No editor paste wiring, clipboard reading or HTML/SVG/text paste fallback (phase 8, `editor.rs:907`).
- No change to `app/`, the FFI, or Rust behaviour apart from the test-only CLI subcommand.

## Implementation Notes

- `Decode(html) ([]Node, bool, error)`: Rust's `decode` is a `Result<Option<..>>`, so the Go side returns the error too (`ok=false, err=nil` is `None`). `Node` is the `*jsonv.Object` plus its Figma box.
- `nalarupa-cli figma <clipboard.html>` prints `[[node, [x, y, w, h]], ...]`, `null`, or `{"error": ...}`.
- Fixtures (`core-go/testdata/figma/`) are written by `NALARUPA_FIGMA_FIXTURES=1 go test -run TestWriteFixtures ./figma/` (`fixture_test.go` holds a kiwi encoder and a wider schema than `app/scripts/figma-fixture.ts`): the card, the card re-encoded as a `fig-jam.` archive with a raw-deflate message and line-broken base64, `shapes` (transforms, flips, the three gradient kinds with the angular seam, image and disabled/blended paints, effects, polygon, arc, line, text variants, independent borders, masks, fill/effect/text styles, a two-region vector with curves), `instances` (component properties, swaps by property and by override, nested and derived overrides, variable modes and bound fields, a missing component), and 12 malformed payloads. `live/budget.html` (instances nested 50 wide, three deep) is compared live only: its output is megabytes.
- Errors worded by the base64 and decompression libraries (Rust `base64`/`miniz_oxide`/`zstd` against Go's `encoding/base64`/`compress/flate`/klauspost) cannot match word for word; parity treats two such `bad Figma clipboard data: ...` errors as equal. Every other message, including the 256 MB cap, is compared exactly.
- Trigonometry uses usvg's correctly rounded `Sin`/`Cos`/`Atan2` (now exported): `math.Atan2` matched the MSVC libm under GOAMD64=v1 but was one ulp off under v3 (fused multiply-add inside Go's math). Products added or subtracted are wrapped in `float64()` against fusing.
- Rust builds `styles` from a `HashMap` (random order); Go walks the props in first-seen order. Only colliding style keys could tell them apart.
- Kiwi strings decode with Rust's `from_utf8_lossy` rule (one U+FFFD per maximal invalid subpart); blob hex pairs parse as `u8::from_str_radix` (a `+` sign is accepted). Kiwi arrays are not preallocated from the declared count.
- zstd uses libzstd's default 128 MB window limit, single-threaded, read through a 256 MB + 1 limit.
